SQLite 3.54.1 как управляемый APK

Этот каталог заменяет пакет sqlite-libs в поддерживаемом Alpine 3.24. Он не меняет Python, протокол приложения или расположение системной библиотеки. APKBUILD сохраняет флаги Alpine, SONAME libsqlite3.so.0, лицензию blessing и автоматическое вычисление зависимостей. Дополнение split-пакета libraries - копия upstream LICENSE.md, поскольку остальные split-пакеты не попадают в runtime.

Статус: подготовлен исходный контракт. Реальная сборка, установка, обе архитектуры, скан образа и E2E должны пройти отдельно. options="!check" соответствует Alpine: autoconf-архив не содержит полного upstream test suite. Это не результат успешного запуска тестов.

Входы и артефакты

База - выбранный интегратором официальный Python 3.12.16 / Alpine 3.24 с полным digest. Builder и runtime обязаны иметь один target platform. Запускать независимо для linux/amd64 (APK x86_64) и linux/arm64 (APK aarch64); не собирать библиотеку в BUILDPLATFORM и не переносить между архитектурами. Один APKBUILD и одинаковые исходники используются для обеих архитектур.

Контракт Docker stage

Фрагмент для интеграции в основной Dockerfile, не самостоятельный Dockerfile. Build context - корень репозитория. Базовый image digest и числовой SOURCE_DATE_EPOCH задаются интегратором. Флаг -d отключает проверку/установку build dependencies; все они установлены предыдущим RUN. Он не отключает проверку source SHA-512. Abuild 3.17.0 соответствует Alpine 3.24.

# Existing pinned Python 3.12 / Alpine 3.24 stage, target platform.
RUN apk add --no-cache alpine-sdk abuild=3.17.0-r0 readline-dev unzip
COPY backend/runtime/sqlite/ /build/sqlite/
ARG SOURCE_DATE_EPOCH
RUN --mount=type=tmpfs,target=/tmp/signing \
    SOURCE_DATE_EPOCH="$SOURCE_DATE_EPOCH" sh /build/sqlite/build-apk.sh

# Only these public files are eligible for copying from the builder:
# /out/sqlite-libs-3.54.1-r0.apk
# /out/sekvyr-sqlite-build.rsa.pub
# /out/build-info.txt and /out/SHA256SUMS

Builder содержит компилятор, readline headers и abuild. В runtime переносится только libraries APK; CLI, static/dev/doc APK, компилятор, readline и build tree не переносятся. Фактическая runtime closure должна подтверждаться APK metadata и ELF NEEDED: ожидается musl, без зависимости библиотеки от readline.

Скрипт отказывается работать без настоящего отдельного tmpfs mount в /tmp/signing, непустой signing/output каталог не переиспользует. RSA private key, HOME и пользовательский abuild.conf существуют только на tmpfs в одном RUN. Не добавлять abuild-keygen -i, копирование private key, tracing оболочки, cache mount на signing path или секреты в ARG/ENV/COPY. Abuild подписывает APK и индекс штатным способом; наружу выходит только публичный ключ. Созданный индекс не нужен runtime.

Перед экспортом скрипт обязательно проверяет исходный APK правильным публичным ключом. Затем он требует отказ с другим ключом под тем же basename и отказ для копии APK с измененным байтом. Дополнительный private key, каталог неверного публичного ключа и поврежденная копия находятся только на signing tmpfs. Если хотя бы один отрицательный случай проходит verification, сборка останавливается до экспорта APK. Эти проверки станут actual evidence только после успешного выполнения реальной сборки.

Установка с временным доверием

Этот RUN выполняется после обычного Alpine upgrade. Временный ключ доверяет только локальному APK; каталог доверия не устанавливается в /etc/apk/keys. Предварительно существующие runtime зависимости должны уже удовлетворяться без сети. Выходной каталог builder монтируется read-only из stage sqlite-build: APK и публичный ключ не копируются в постоянные runtime layers.

RUN --network=none \
    --mount=type=bind,from=sqlite-build,source=/out,target=/tmp/sqlite-artifacts,ro \
    --mount=type=tmpfs,target=/tmp/sqlite-keys \
    cd /tmp/sqlite-artifacts && \
    sha256sum -c SHA256SUMS && \
    cp sekvyr-sqlite-build.rsa.pub /tmp/sqlite-keys/ && \
    apk --no-network --keys-dir /tmp/sqlite-keys verify sqlite-libs-3.54.1-r0.apk && \
    apk --no-network --keys-dir /tmp/sqlite-keys add /tmp/sqlite-artifacts/sqlite-libs-3.54.1-r0.apk

Сохранять APK database, package ownership, SONAME и исходную лицензию. Не использовать untrusted install, force-overwrite, ручное удаление .so, shadow в /usr/local или очистку package metadata. Оба mount исчезают после RUN, а установленная библиотека и ее APK metadata остаются. Ошибка dependency resolution должна останавливать сборку.

Воспроизводимость и проверка

Закреплены исходники, версия, флаги и SOURCE_DATE_EPOCH. Для воспроизводимости payload также нужны digest builder и точные версии всех toolchain packages; build-info.txt фиксирует архитектуру и основные версии, но не заменяет полный builder inventory. Эфемерный случайный signing key меняет подпись и SHA подписанного APK между независимыми сборками. Не называть эти signed artifacts побайтово воспроизводимыми.

  1. Проверить подпись правильным ключом и отказ с чужим ключом/поврежденным APK, оба target platform; inventory должен показывать ровно sqlite-libs 3.54.1-r0.
  2. В финальном image запустить python /build/sqlite/verify-runtime.py (тестовый файл можно смонтировать read-only): exact SQLite version/source ID, стандартные compile options, FTS5 prefix query с минимальным отрицательным rowid, foreign keys, фактически загруженная /usr/lib библиотека и ее APK owner. Скрипт выводит только безопасные результаты, использует :memory:.
  3. Проверить scanelf/readelf у CPython _sqlite3: NEEDED libsqlite3.so.0; исключить другие загружаемые SQLite .so и private signing material во всех слоях, экспортах cache и build context.
  4. Прогнать SQLite migrations, CRUD/transaction/backup/restore, полный backend suite и PostgreSQL locking/migration suite. Затем реальные TLS/auth/Plain/E2E2 Kubernetes сценарии и UID/GID/drop-privileges/signal/shutdown проверки нового entrypoint.
  5. Повторить полный image scan, включая unfixed, Python dependency audit, SBOM и provenance. Отсутствие записи в Alpine secdb не считается исправлением SQLite. Нельзя заменять реальную CVE проверку только тестом SQL без ASAN: regression здесь функциональный.
