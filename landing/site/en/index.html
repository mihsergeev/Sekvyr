Secrets live in a panel, not in chat messages

People edit values in the web UI; servers and clusters pull them on their own and keep their .env files up to date. The admin UI answers only your addresses, the machine API is public and only reads secrets: two separate surfaces, not one with caveats.

What it does

Everything a secrets vault is usually installed for, and nothing beyond that.

Projects and environments

A project holds environments such as dev, stage and prod; those hold folders and keys. .env import and export, inherited values, Ctrl+K search across the whole panel. The navigation is built for hundreds of projects.

Versions and rollback

Values are never overwritten: every edit is a new version. You can see what a key held yesterday, diff two versions and see what changed in a week. A deletion is a version too, and therefore reversible.

Permissions enforced by the API

Who, where and what, with list and read kept apart: a developer sees which variables an app needs without seeing production passwords. A grant can expire and can require two-factor authentication.

Approvals by role

An edit from a role below the project threshold waits for someone more senior and does not reach the servers until then. Authors cannot approve their own edits, and only the owner changes the threshold.

One command per server

The panel gives you a line with a one-time token; the agent installs itself and receives its own credentials, of which the panel keeps only a hash. Access is granted with a click, and a change reaches the service on its own. The agent updates itself too, only on a valid release signature.

Kubernetes without static secrets

A pod presents a short-lived ServiceAccount token issued for the panel specifically, and the panel checks the signature against the cluster keys. If you already run External Secrets Operator, that works too.

Migration from Infisical and Vault

A separate screen with a preview: you see what arrives new and what is already there. Existing values are not overwritten by default, and the panel does not store the source credentials.

Value hygiene

A key carries a note on why it exists and a date by which it must be replaced, and the panel reminds you ahead of time. Missing required keys show in every environment, and changeme in production gets caught on its own.

Operations

Encrypted backups with a freshness check, one-command restore, upgrades that take a backup before the migrations, a watchdog outside the containers. Telegram and webhook alerts, a weekly digest of changes.

Security

The project's main rule: compromising the database must not yield the values. Everything else is an implementation detail of that rule.

Three key levels

A value is encrypted with its environment key, which is wrapped by the root key. Ciphertext is bound to its place, so a row cannot be moved to another environment or swapped for someone else's value.

The panel starts sealed

Until the root key is entered, nobody can read values, the owner included. The key is kept as shares (3 of 5 by default), as one key you enter after every restart, or as a file on the server.

Servers only read

A connected machine cannot change or delete a secret: the machine API has no such routes at all, and a test in CI checks that rather than a promise in the documentation.

Hash-chained audit log

Every entry carries the hash of the previous one, and the panel rechecks the chain daily. A copy of the entries can go to an external webhook, otherwise the log could be trimmed together with the database. Values never get into the log.

Browser-side encryption

For selected projects: values are encrypted with a key the server never has. The price is honest: a forgotten project password means the values are lost.

Emergency access

Every value in one sealed file under your password. A separate utility opens it without the panel and without a network, for the day the panel is gone.

How it differs

Sekvyr does not try to replace Vault at everything. It covers the more common case: dozens of servers, a couple of people on infrastructure, and a wish to see everything in one place.

Install

A Linux server with ports 80 and 443 free. The command installs Docker if it is missing, brings up Caddy with a Let's Encrypt certificate, starts the panel with nightly encrypted backups and a watchdog, and prints the address and the owner password.

$curl -fsSL https://raw.githubusercontent.com/mihsergeev/Sekvyr/main/ops/quickstart.sh | sudo sh

No domain of your own is needed: the panel works on <server-ip>.sslip.io right away, with an ordinary certificate. For a permanent install pass your domain and the addresses allowed into the admin UI:

$curl -fsSL https://raw.githubusercontent.com/mihsergeev/Sekvyr/main/ops/quickstart.sh | sudo sh -s -- --domain sekvyr.example.com --allow-ips "203.0.113.10"

Log in and change the password, turn on two-factor authentication. The installer's password sits in .env in plain text.

Create the vault. The root key shares are shown once and never again: hand them to different people.

Set up alerts. A panel holding secrets should not fail quietly.

Connect your first server. The panel shows the ready-made agent install command.

Manual install, your own HTTPS proxy, Kubernetes and backups are covered in the documentation.
