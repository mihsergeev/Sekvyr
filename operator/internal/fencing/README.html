Trial fencing: граница API

Пакет разрешает явно включенный HA trial для одной установки и одной journal log/view. Lease выбирает кандидата; запись разрешают подписанный актуальный grant, все объектные барьеры и независимая подписанная activation. Ни Lease, ни локальная память fencer не заменяют онлайн canonical journal.

HTTPS и аутентификация

Команда /sekvyr-fencer запускается только с --allow-trial-fencing=true. По умолчанию слушает TLS на 9443. Флаг --config читает административный JSON, --journal-config читает sekvyr-journal-client-config-v1 SDK с фиксированным gateway origin, CA и путями mTLS certificate/key. Прямые S3 credentials и ключи данных клиенту не передаются. --signing-key принимает Ed25519 PKCS8 PEM; --tls-cert и --tls-key задают TLS identity.

POST /v1/installations/{installation_id}/acquire
Authorization: Bearer <bound projected JWT, audience sekvyr-fence>
{"bootstrap_generation":1,"expected_lease_holder_identity":"<pod-name>_<fixed-process-uuid>"}

POST /v1/installations/{installation_id}/barriers
POST /v1/installations/{installation_id}/ready
{"grant_hash":"<lowercase SHA-256 hex>"}

Response: {"grant":<signed journal grant>,"grant_hash":"...","active":false}

Acquire повторно проверяет TokenReview, bound Pod/SA/namespace UID и точный Lease holder. При CASConflict новая попытка заново читает Lease. Term монотонен; grant содержит exact enrollment objects, authority digest и canonical snapshot. Barriers меняет только public fence-аннотацию каждого закрепленного объекта с UID/resourceVersion CAS, повторно проверяет все барьеры и записывает activation. Ready сверяет активный онлайн grant, текущего владельца и все барьеры. Неуспех не активирует частичную установку барьеров.

GET /healthz проверяет процесс. GET /readyz проверяет доступность актуального journal/enrollment; это не обещание завершения всех барьеров или синхронизации данных. Bearer перечитывается клиентом из файла для каждого запроса. Redirect и proxy отключены, origin фиксирован, TLS validation обязательна.

Admission и неизменяемая writer session

POST /admit принимает Kubernetes AdmissionReview v1. Решение использует только old/new версии одного объекта и онлайн canonical journal. Kubernetes GET, Lease GET и побочные записи в admission отсутствуют. Оператору нужны exact SA UID, bound Pod identity, актуальная activation, неизменный fence, UID/resourceVersion и аннотация secrets.sekvyr.ru/write-session с fixed session grant hash. Старый процесс не может обновить сессию, скопировав fence из GET. Fencer SA разрешено только строгое увеличение fence; data/spec/прочие аннотации сохраняются.

Writer декорирует client.Client для конкретной неизменяемой сессии. Разрешены Update и проверенные CAS Patch закрепленных Secret/Deployment. Create, Delete, DeleteAllOf, Apply и все mutating subresource methods отвергаются. Изменение canonical snapshot инвалидирует grant и требует нового term, барьеров и activation; барьеры сами не меняют Secret data, data revision или Deployment pod template.

Предположения и проверки

Admin config и enrollment закрепляют namespace/SA/Lease/object UID. Три immutable Opaque material Secret проверяются при старте; материал не перечитывается admission. Signer должен оставаться разрешенным текущей независимой authority. Явный bootstrap/recovery субъект сопоставляется по точным username и UID; это доверенная административная граница.

Unit tests включают fresh Lease на CAS retry, повторный процесс в том же Pod, snapshot advance, неполные барьеры, точную Pod identity, недоступный journal, metadata-only барьеры, zero cross-object reads в admission, реальный HTTPS round trip, token rotation, отказ redirect и запрещенные writer API. In-memory ledger в unit tests не доказывает WORM или независимость storage.

Гарантия задержанной записи предполагает честный API server с монотонными resourceVersion и storage CAS. Raw etcd rollback с откатом RV и сохранением уже одобренного запроса, компрометация действующего SA/администратора, Byzantine gateway и потеря единственного trial узла не покрыты. Production HA/WORM требуют самостоятельного deployment и storage аудита.
