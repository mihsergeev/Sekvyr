Проверки этапа 2 в отдельном kind

Проверяются настоящие Kubernetes API admission/CEL, Helm-установка, RBAC, projected ServiceAccount tokens и безопасный отказ каркаса. Реальные E2E2 sync, witness, durable ledger, обновление Secret и rollout не реализованы и этими проверками не подтверждаются.

Нужны Linux/WSL, Docker через sudo без пароля, Helm, Python 3 и PyYAML. Все kubectl-команды направлены только внутрь node sekvyr-stage2-control-plane с его собственным admin.conf. Текущий пользовательский Kubernetes context не используется. kind 0.33.0 скачивается с проверкой официальной checksum, node 1.37.0 закреплен digest.

bash operator/tests/kind/prepare.sh
# Сохранить напечатанный TASK_DIR.
python3 operator/tests/kind/admission.py --chart operator/charts/sekvyr-operator
# Загрузить собранный для проверки образ в sekvyr-stage2, сохранив digest reference.
python3 operator/tests/kind/run.py \
  --chart operator/charts/sekvyr-operator \
  --task-dir /tmp/sekvyr-stage2.REPLACE \
  --image-repository example.invalid/sekvyr-operator \
  --image-digest sha256:REPLACE
bash operator/tests/kind/cleanup.sh /tmp/sekvyr-stage2.REPLACE

В WSL с cgroup v1 только тестовый kubelet получает failCgroupV1: false. Системные настройки WSL/Docker не меняются. Это проверка API/оператора, а не приемка конфигурации production node.

Bootstrap fixtures создаются динамически в тестовом namespace. Поля node/trust удовлетворяют только проверке метаданных этапа 2 и не являются доверенным криптографическим bootstrap. Значения ключей и JWT в репозиторий и вывод не попадают. Проверяются claims и наличие обновляемой проекции, но часовая ротация kubelet не ожидается и не объявляется пройденной.

Результат сохраняется в TASK_DIR/results.json без секретов. Cleanup удаляет только этот кластер и его временный kubeconfig, оставляя образы и чужие контейнеры. При остановке теста выполнить cleanup вручную. Повтор полного run требует чистых тестовых namespaces.
