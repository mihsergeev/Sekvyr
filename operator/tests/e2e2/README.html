E2E2: независимые тестовые векторы

Все данные синтетические и публичные. Scalar ноды и ключ чтения намеренно известны всем участникам теста. Они не являются учетными данными и не предназначены для установки в кластер.

Python reference использует Ed25519, P-256 ECDH, HKDF-SHA256 и AES-GCM из cryptography. Node отдельно повторяет проверки через WebCrypto. Go потребляет те же байты через production API кодека. Тестовые программы не подключаются к панели или witness.

Что проверяется

  • Точные canonical bytes, подпись, fingerprint, ECDH shared secret, HKDF key, AES-GCM plaintext reader wrapper.
  • Контрольные символы в значениях, U+2028/U+2029, HTML-sensitive символы, astral Unicode и сохранение decomposed Unicode без нормализации.
  • Полный снимок, сортировка UTF-8 вместо UTF-16, уникальность tuples и parent contexts, NFC и запрет управляющих символов только в metadata.
  • Подписанные и зашифрованные некорректные payload: неизвестные/пропущенные/null поля, чужой context, неверный формат и размер ключа, дубли escaped имен, malformed UTF-8, lone surrogates.
  • Дубли JSON, числа 1.0/1e0, глубина, byte bounds, uint64 overflow, неканонический Base64url, подмена checkpoint hash, неподходящая кривая и некорректные Ed25519 public keys.

Для 45 snapshot и 20 wrapper cases перед семантической проверкой независимо проверяется настоящая Ed25519-подпись. WebCrypto теперь проверяет каждый расшифрованный payload, включая отрицательные случаи, через отдельный bounded UTF-8/JSON parser с запретом дубликатов и неканонических значений.

Панель проверяет подпись и внешние metadata, но не получает AES read key. Поэтому 24 некорректных encrypted snapshot payload и 13 wrapper payload остаются непрозрачными для нее и отклоняются reader после расшифрования. Эта граница закреплена в public-layer-matrix.json и тестах production Python validator.

Authority corpus отдельно проверяет pinned witness, scope/genesis, nonce, floor/cursor, digest, роли ключей, точную JSON shape и границы чисел. Входящий witness key не становится pin. Новый publisher в подписи уже независимо закрепленного witness допустим; его административная история проверяется Go journal при полном replay. Genesis без опубликованного snapshot допустим для Go authority, но не становится публикуемой projection панели. Проверку prime subgroup для доверенных Ed25519 keys выполняет production Go; публичные WebCrypto pins созданы из заведомо публичных тестовых seeds.

Production Python boundary проверяется в backend/tests/test_e2e2_parity.py. Эти offline тесты не заменяют живую приемку панели, storage и Kubernetes и не заявляют независимость испытательного storage от администратора стенда.

reference.py --patch выводит patch обновления публичных fixtures, а обычный запуск проверяет отсутствие расхождений. Изменение fixtures требует отдельного просмотра, это не команда принятия новых значений по сети.

Граница канонизации

Используется ограниченный профиль с фиксированными ASCII property names и целыми счетчиками в строках, а не универсальная JCS-библиотека. RFC 8785 требует сохранять Unicode scalar strings и отклонять lone surrogates. Обычный encoding/json имеет другие правила escaping и обработки некорректного Unicode, поэтому одной успешной JSON-десериализации для проверки протокола недостаточно.

Ограничение Node 24 HKDF

При проверке обнаружено: встроенный HKDF в Node 24.15 отклоняет info длиннее 1024 байт. Заголовок корректного снимка с parent references может превышать этот размер. Это ограничение реализации, а не изменение согласованного протокола: domain и полный JCS(header) не сокращаются и не хешируются вместо исходных байтов.

Тестовый Node reference выполняет HKDF-SHA256 через WebCrypto HMAC: Extract и один Expand block, L=32. Проверяется официальный PRK и первый блок OKM из RFC 5869 Appendix A.1, совпадение со встроенным HKDF на info длиной до 1024 байт и совместимость с Python и Go на полном заголовке с 16 parent references. Ограничение info в документации Node 24.15.

Это проверочный reference, а не production JavaScript или тест браузерного интерфейса. Ограничение нельзя скрывать подменой входа KDF или неявным изменением wire format.

Эти проверки не подтверждают работу durable witness ledger, сетевого сервиса, реальной панели или независимый аудит безопасности. Они проверяют кодек, cryptographic binding и совместимость фиксированных публичных векторов.
