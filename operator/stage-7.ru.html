Sekvyr operator: результат этапа 7

Функциональная приемка и удаление своих ресурсов завершены. Plain и E2E2 доставили секреты в работающие приложения. Проверены изменения, отсутствие лишних рестартов, отказы, ротации и восстановление pending rollout. Сохраняются 9 HIGH OS CVE в trial backend и явно принятое пользователем отличие глобального IPv6-состояния хоста. Это результат для рассмотрения перед этапом 8, без допуска production.

Срез 2 ноября 2026 года. Chart 0.1.0, appVersion 0.1.0-stage7-trial. Продуктовая версия не менялась. Commit, push, выпуск, production-развертывание и этап 8 не выполнялись.

Проверенная цепочка

Plain: закрепленная HTTPS-панель → новая авторизация → полный ответ → Kubernetes Secret. E2E2: подписанный ciphertext и reader wrap → независимые witness/journal и fencing → расшифровка → Secret. Приложение проверялось через envFrom, Secret volume с reload и файл неизмененного опубликованного init + agent sidecar 1.0.3. Регрессия старого агента относится к Plain; его E2E2-поддержка не заявляется.

Начальное создание и включение rollout не создают исторический restart. Изменение envFrom подтверждается новым процессом и одним ReplicaSet; одинаковые значения сохраняют data revision, Pod и процесс. Volume и файл агента обновляются в том же процессе. Обновление объекта Secret само по себе не засчитывалось как получение значений приложением.

Сетевые пути продукта

На том же Plain Pod/CID до исправления DNS работал, а новые TCP к панели/API завершались timeout. После 7 точечных NetworkPolicy получены строгие TLS HTTP 200 к панели и API; upstream S3 TCP остался запрещен. Сохранены UID/spec всех 21 прежних policy и 6 namespace, default-deny не снят; всего 28 policies. Это конкретные packet probes, не conformance всех путей.

Межnamespace-пути совмещают точные namespace и Pod selectors с портами; API/admission используют закрепленные IP/ports. Новые правила ставятся fresh-run hook после captured Helm install, до первой публикации. Широкие CIDR и открытие isolation к S3 не добавлялись.

История прерываний сохранена

  • Потери SSH/WSL interpreter потребовали read-only восстановления по точным durable Helm/UID captures. Восстановленные locals не выдавались за прежний live frame. Plain initial и OFF наблюдались дальше без повторной публикации/prepare/install; потерянный OFF local before не выдумывался, использованы более ранние сохраненные initial baselines. Env/volume modes проверены по UID, командам, mounts и immutable source bytes.
  • Genesis negative batch прервался с неуточненным TLS/transport отказом. Сохранены 4 genesis, singleton VersionID и retention; отдельные оставшиеся negative calls дали 400/403/403/403 без повторного initialize/append/reset. Исходный batch остался INCOMPLETE.
  • Старые EndpointSlice null и Node/webhook guard ошибки не скрыты: дополнительные цели и точечные продолжения сохраняли историю и pins. Старые OOM при 128/256 MiB устранены trial-конфигурацией 512 MiB / GOMEMLIMIT 384 MiB. Точные VersionID до раннего ремонта отдельно не снимались; их непрерывность не заявляется.
  • Первый upgrade observer ошибочно ожидал неизменных fencer при общем resources. Его attempt остался INCOMPLETE. Продолжение проверило тот же уже выполненный upgrade, обе старые пары и свежую синхронизацию после cutover, без повторного Helm/publish.
  • Первый leader-case остановился на штатном Debouncing до helper/TERM; finally снял pause, candidate A завершил обычный 1-RS rollout. Он остался INCOMPLETE. Исправление допускает ожидание только Debouncing после всех protected checks; unknown reason — hard fail. Только новый закрытый case label/candidate B прошел leader/pending.
  • JWKS run реально сменил signer, но API-server restart оборвал panel port-forward. Finally вернул старый signer. После ремонта только своих panel/witness forwards по прежним UID/TLS pins retirement завершен с сохраненным новым токеном и действующим старым FILE JWT, без повторной смены ключа/manifest. Исходный run остался INCOMPLETE. Новый callback переподключения проверен offline для будущего запуска; его выполнение живьем здесь не заявляется.
  • Strict Docker cleanup удалил CID и volume и остановился на изменении IPAM usage counters пустой сети. Независимое восстановление исходного creator hash изменением только четырех счетчиков IPv4/IPv6 в памяти подтвердило остальные поля. После fresh guard отдельно удален exact созданный network ID. Повтор cleanup и ослабление hash-проверки не выполнялись.

В WSL за 90 секунд отмечены 3 UTC backstep примерно по 2,6 секунды и future renewTime после ответа API. Конкретный компонент перевода часов не установлен; global clock/service experiment не запускался, future-Lease fail-closed не ослаблялся. d328 добавил только закрытые bounded причины Ready-ошибок: лимит ответа 4 КиБ, без произвольных сообщений, дублей и unknown fields; TTL/grants/crypto policy не менялись.

Границы доверия

Plain доверяет авторизованной панели и не дает publisher authenticity, независимой anti-rollback freshness или HA. Его protected state имеет mode Plain/head null, без E2E checkpoint, WitnessReady=Unknown/NotApplicablePlain. Во время отказа последние данные сохраняются; новый или pending rollout требует свежего успешного чтения. Зашифрованный источник не понижается до Plain.

E2E2 требует witness/journal; новый canonical head требует нового grant и metadata barriers даже при одинаковом plaintext, без новой data revision/Pod template. Recovery подписан и закреплен на точных cursor, generation и UID; prepared phase блокирует runtime, несовпадение оставляет RecoveryPending. Cross-system atomic freshness и exactly-once restart не заявляются.

Backend offline JWKS сопоставляет namespace и имя SA. Runtime/admin UID pins и harness creation pins не означают backend SA-UID binding или немедленный отзыв JWT после удаления Pod. Fencer TokenReview — отдельный слой. Retirement kid проверяет новые обмены, не немедленный отзыв уже выданной machine session. Внешние SA/Lease используются через create=false с точными UID, без adoption; immutable ConfigMap сохраняются до reviewed cleanup без consumers.

Один физический host и trial storage не доказывают независимый production WORM, fault domains и power-loss durability. AWS S3, MinIO, другие storage engines/minors, ARM64 и финальный production профиль не объявляются проверенными. Byzantine control plane/storage, root-компрометация и etcd resourceVersion rewind при живом запросе вне гарантий.
