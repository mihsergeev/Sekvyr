# Установка и эксплуатация

[English version](install.md)

## Одной командой

```sh
curl -fsSL https://raw.githubusercontent.com/mihsergeev/Sekvyr/main/ops/quickstart-ru.sh \
  | sudo sh -s -- --domain sekvyr.example.ru --allow-ips "203.0.113.10" --timezone Europe/Moscow
```

Скрипт ставит Docker, если его нет, поднимает `caddy-docker-proxy` для
сертификатов, клонирует репозиторий в `/opt/sekvyr`, генерирует секреты,
поднимает панель из выпущенных образов, заводит ночные шифрованные бэкапы со
сторожем и печатает адрес, логин и пароль. С `--build` образы собираются из
исходников: несколько минут и около 2 ГБ памяти. Выпущенные образы панели
собраны под amd64, поэтому на других архитектурах (и на arm64) скрипт сам
собирает их из исходников.

Что нужно: сервер на Linux со свободными портами 80 и 443 и root. Docker
ставится через `get.docker.com`, git, если его нет, через `apt-get`; на других
системах поставьте git заранее.

Без `--domain` берется `<публичный-IP>.sslip.io`: этот DNS отвечает адресом,
записанным в самом имени, поэтому Let's Encrypt выдает для него обычный
сертификат и панель открывается по https сразу.

`--allow-ips` задает адреса, которым открыта **админка**. Машинный контур
остается открытым всем, в этом замысел: серверы и кластеры забирают секреты из
сетей, которых не может быть в белом списке администраторов. Пустой список не
запрещает никому, и для хранилища секретов это не то состояние, в котором стоит
жить.

Повторный запуск - это обновление. Как и `ops/update.sh`, скрипт сначала
снимает бэкап работающей панели, и без удачного бэкапа ничего не меняется.
Потом переводит код на последний выпуск (при сборке из исходников - на
последний `main`), а бэкенд при старте применяет миграции. Готовый `.env`
скрипт не переписывает, кроме строк `COMPOSE_FILE` и `SEKVYR_IMAGE_TAG`; свои
оверлеи в `COMPOSE_FILE` остаются в конце списка. Пароли повторный запуск не
печатает и берет из `.env` домен и белый список, даже если в командной строке
задано другое, и прямо об этом говорит. Сменить домен или список - это правка
`SEKVYR_DOMAIN`, `SEKVYR_PANEL_URL` и `SEKVYR_ALLOW_IPS` в `.env` и
`docker compose up -d`.

Панель, поставленная с `--dir`, обновляется с тем же `--dir`. Без него скрипт
найдет панель в ее каталоге и остановится, ничего не изменив: вторая копия в
`/opt/sekvyr` под тем же именем проекта compose могла бы забрать ее контейнеры.

## Что получилось

| Часть | Где | Зачем |
| --- | --- | --- |
| `db` | внутренняя сеть | Postgres 18, только шифротекст значений |
| `backend` | внутренняя сеть | API панели и машинный контур |
| `frontend` | за caddy | статика и заголовки безопасности |
| `caddy` | 80/443 | TLS, разделение контуров, белый список |

Данные лежат в `<установка>/data`, корневой ключ, если он хранится на сервере, в
`<установка>/secret`. Каталоги разные намеренно: бэкап базы не должен увозить
ключ вместе с шифротекстом.

Сеть `caddy` заводится с IPv6. Без него Docker пропускает соединения по IPv6
через свой прокси, caddy видит вместо клиента шлюз моста, и белый список не
пускает никого, кто пришел по IPv6.

## Первые шаги

1. **Смените пароль и включите второй фактор.** Пароль из вывода установщика
   лежит в `.env` открытым текстом.
2. **Заведите сейф** в разделе "Сейф". До этого панель заперта и ничего не
   хранит. Держать корневой ключ можно тремя способами:
   - **Доли** (по умолчанию 3 из 5): ключа целиком нет ни у кого. Доли
     показываются один раз: раздайте их разным людям и положите в разные места.
     После каждого перезапуска панель ждет, пока введут порог долей.
   - **Один ключ, который вы вводите сами** после каждого перезапуска. На
     сервере его нет, поэтому дамп, бэкап и украденный диск без него
     бесполезны.
   - **Один ключ на сервере**: панель поднимается сама, а root на хосте
     означает доступ ко всем значениям. Сохраните ключ в
     `<установка>/secret/root.key` с правами 0400 и владельцем 10001, задайте
     `SEKVYR_ROOT_KEY_FILE=/secret/root.key` в `.env` и выполните
     `docker compose up -d backend`. Без этого после перезапуска панель
     окажется запертой.
3. **Настройте оповещения** в разделе "Обслуживание". Панель сообщает о том, о
   чем нельзя узнать позже: сейф заперли или открыли, вход заблокирован после
   серии попыток, собран аварийный архив, цепочка журнала перестала сходиться
   (панель пересчитывает ее раз в сутки). Туда же уходят правки боевых
   окружений (`SEKVYR_ALERT_ON_ENVS`, по умолчанию `prod production`), новые
   замечания к значениям, подходящие сроки замены, серверы, переставшие
   забирать секреты, и недельная сводка правок. Значений в этих сообщениях нет,
   только место, имя ключа и автор.
4. **Проверьте бэкап.** Там же видно, когда он снимался в последний раз.
   Пароль шифрования бэкапов лежит в `<установка>/secret/backup.pass`: сохраните
   его там же, где доли ключа. Подробности: [backup.ru.md](backup.ru.md).
5. **Добавьте первый сервер** на странице "Серверы": панель покажет готовую
   команду установки агента. После первого отчета там будут видны система, оба
   адреса и версия агента. Устаревшая версия подсвечивается, и агент
   обновляется сам, только вперед: назад его может отправить лишь человек
   командой `sudo sekvyr update --allow-downgrade --restart sekvyr-agent` на
   ноде. Без `--restart` меняется только бинарь на диске, а работающая служба
   остается на прежней версии до перезапуска.
6. **Осмотритесь в проекте.** Ctrl+K открывает поиск по всей панели: проекты,
   окружения, серверы, ключи. В настройках проекта задаются обязательные ключи
   (панель покажет их нехватку в каждом окружении) и срок, после которого
   значение считается давним.

## Установка вручную

Нужны Docker с Compose 2.24 или новее и git. Сборка из исходников просит около
2 ГБ памяти, выпущенным образам это не нужно.

### За caddy-docker-proxy, как ставит quickstart

```sh
# сеть, за которой следит caddy, с IPv6 (см. выше);
# Docker до 27 нужна еще подсеть: --subnet fd00:cad::/64
docker network create --ipv6 caddy

# сам caddy-docker-proxy, если на сервере его еще нет
mkdir -p /srv/caddy && cd /srv/caddy
cat > compose.yml <<'YML'
services:
  caddy:
    image: lucaslorentz/caddy-docker-proxy:2.13-alpine
    restart: unless-stopped
    logging:
      driver: json-file
      options: {max-size: "10m", max-file: "3"}
    ports: ["80:80", "443:443"]
    environment:
      CADDY_INGRESS_NETWORKS: caddy
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./data:/data
    networks: [caddy]
networks:
  caddy:
    external: true
YML
docker compose up -d

# панель, на последнем выпуске (пре-релизы пропускаются):
# образы есть только у выпусков
git clone https://github.com/mihsergeev/Sekvyr.git /opt/sekvyr
cd /opt/sekvyr
git checkout "$(git tag -l 'v*' --sort=-v:refname | grep -Ex 'v[0-9]+\.[0-9]+\.[0-9]+' | head -n 1)"
cp .env.example .env
chmod 600 .env
$EDITOR .env
docker compose up -d
```

Что задать в `.env`:

| Переменная | Значение |
| --- | --- |
| `SEKVYR_ADMIN_PASSWORD` | пароль владельца, от 12 символов |
| `SEKVYR_JWT_SECRET` | `openssl rand -hex 32` |
| `SEKVYR_DB_PASSWORD` | `openssl rand -hex 24` |
| `SEKVYR_DOMAIN` | домен панели |
| `SEKVYR_PANEL_URL` | тот же домен с `https://`: из него строятся команды установки и ссылки в оповещениях |
| `SEKVYR_ALLOW_IPS` | адреса, которым открыта админка |
| `SEKVYR_TRUSTED_PROXY_HOPS` | `2`: caddy и nginx фронтенда |
| `COMPOSE_FILE` | `compose.yml:compose.ghcr.yml:compose.caddy.yml` |
| `SEKVYR_IMAGE_TAG` | выпуск, на который переключились, без `v` (его покажет `git describe --tags`) |

Значение со знаком `$` пишите в одинарных кавычках: docker compose подставляет
`$ИМЯ` в `.env`, и часть пароля без кавычек молча пропадет.

Чтобы собрать из исходников, задайте `COMPOSE_FILE=compose.yml:compose.caddy.yml`,
`SEKVYR_IMAGE_TAG` не нужен, и запускайте `docker compose up -d --build`.
`COMPOSE_FILE` важен в обоих случаях: `ops/update.sh` и любой голый
`docker compose up` берут список файлов из него, и без оверлея caddy фронтенд
пересоздается без меток, а панель пропадает со своего домена. С заданным
`COMPOSE_FILE` docker compose сам больше не подхватывает `compose.override.yml`:
свой оверлей допишите в список.

Сборка из исходников, переключенная на метку, как выше, стоит не на ветке, и
`ops/update.sh` без аргумента откажет: называйте выпуск явно,
`sudo ops/update.sh v1.2.0`.

Панель не поднимется со слабым секретом подписи токенов и с паролем владельца
по умолчанию. Это не придирка: со слабым секретом токен владельца мог бы
подписать себе кто угодно.

### За своим HTTPS-прокси

Базовый `compose.yml` ставит панель на `127.0.0.1:8080`, HTTPS перед ней -
ваша часть. Две вещи, которые стоит держать в голове:

- `SEKVYR_TRUSTED_PROXY_HOPS` - число прокси перед бэкендом: `2` с вашим
  прокси (ваш и nginx фронтенда), `1` только если перед панелью нет ничего,
  например за SSH-туннелем. При неверном числе журнал и лимитер входа видят
  адрес прокси, все клиенты схлопываются в один ключ, и один перебор пароля
  закрывает вход всем.
- `/api/v1/machine/*` должен быть открыт вашим серверам, а все остальное -
  закрыто для всех, кроме администраторов, как это делает `compose.caddy.yml`.

### Бэкапы и сторож

quickstart заводит их сам, вручную это две строки:

```sh
echo '17 3 * * * root /opt/sekvyr/ops/backup.sh' > /etc/cron.d/sekvyr-backup
echo '*/5 * * * * root /opt/sekvyr/ops/panel-watchdog.sh' > /etc/cron.d/sekvyr-watchdog
chmod 644 /etc/cron.d/sekvyr-backup /etc/cron.d/sekvyr-watchdog
```

Расписание запускает скрипты прямо из каталога панели, поэтому обновление
обновляет и их. Настройки и восстановление: [backup.ru.md](backup.ru.md).

## Обновление

```sh
cd /opt/sekvyr                # или каталог, переданный quickstart через --dir
sudo ops/update.sh            # до последнего выпуска, а при сборке до последнего main
sudo ops/update.sh v1.2.0     # до метки
```

Сначала снимается бэкап, потом обновляется код и накатываются миграции. Если
бэкап не удался, обновление не начинается: миграции необратимы, и "откатимся,
если что" без свежего дампа - это надежда, а не план.

На выпущенных образах панель переходит от выпуска к выпуску: код рядом и образы
должны быть одной версии, и `ops/update.sh` держит `SEKVYR_IMAGE_TAG` в ногу с
меткой, на которую переключился. Образы нового выпуска скачиваются еще до
бэкапа. Если они не скачались (нет доступа к ghcr.io, или выпуск помечен
несколько минут назад и CI его еще собирает), скрипт останавливается, и не
меняется ничего.

Образы postgres и caddy `ops/update.sh` не обновляет: их метки зафиксированы в
compose, а новый образ базы - отдельное решение. Свежие исправления той же
метки приезжают командами `docker compose pull db` (и `caddy`, если он из
этого compose) и `docker compose up -d`, после бэкапа.

## Обслуживание

| Скрипт | Что делает |
| --- | --- |
| `ops/backup.sh` | дамп, шифрование, ротация, отметка для панели, копия на другую машину |
| `ops/restore.sh` | восстановление из бэкапа со страховочным дампом |
| `ops/panel-watchdog.sh` | сторож вне контейнеров: молчание панели, запертый сейф, сломанный канал |
| `ops/breakglass.py` | аварийный доступ к значениям без панели |
| `ops/update.sh` | обновление с бэкапом перед миграциями |

Скрипты работают от root, как и расписание, которое их запускает: у `.env`
права 0600, и принадлежит он, как и весь каталог панели, обычно root. Скрипт,
запущенный пользователем без доступа к ним, останавливается, ничего не начав,
и просит `sudo`.

Скрипты и их оповещения говорят на языке `SEKVYR_LANG` из `.env` (quickstart
ставит язык того скрипта, которым панель установлена), иначе на языке локали,
по умолчанию по-английски.

## Как отключить сервер

На самом сервере:

```sh
curl -fsSL https://sekvyr.example.ru/api/v1/machine/install.sh | sudo sh -s -- --uninstall
```

Скрипт остановит агента и уберет юнит, бинарь, конфиг с секретом машины, ключ
ноды, шифрованную копию значений и файлы в `/run/sekvyr`. Затем удалите сервер и
в панели (Серверы, меню сервера): машинный контур нарочно ничего не умеет
удалять, поэтому до этого учетка машины продолжает действовать.

## Своя сборка агента

Панель отдает бинарь агента, только если его хеш совпал с подписанным
`agent/manifest.json`, а агенты ставят обновление, только если подпись сошлась
с ключом, вшитым в них. Форк, в котором агент изменен, подписывает свои выпуски
сам:

```sh
python ops/agent_release.py --keygen      # один раз: пара ключей, закрытую половину держите офлайн
SEKVYR_AGENT_KEY=... python ops/agent_release.py --sign   # собрать и подписать agent/VERSION
```

Подпись собирает агента в том же закрепленном образе Go, что и образ панели,
поэтому хеши совпадут с тем, что панель будет раздавать. В репозиторий уходят
`agent/pubkey.txt` и `agent/manifest.json`. Агенты, собранные с другим ключом,
ваши обновления не примут: переустановите их командой из панели.

## Если что-то не так

```sh
docker compose logs --tail=80 backend      # что говорит панель
docker compose exec -T backend python -c \
  "import urllib.request;print(urllib.request.urlopen('http://localhost:8000/api/health').read().decode())"
sudo grep -E '^(ts|sealed|alerts_ok)=' data/heartbeat   # пульс: время, состояние замка, канал оповещений
```

В файле пульса лежат еще токен бота и адрес вебхука, поэтому команда выше
показывает только строки состояния: целиком файл в чаты и тикеты не несите.

Частые случаи:

- **Панель отвечает `sealed`.** Сейф заперт: откройте его долями или ключом.
  После перезагрузки хоста это нормальное состояние, если ключ не лежит на
  сервере (`SEKVYR_ROOT_KEY_FILE`).
- **Сертификат не выдан.** Let's Encrypt считает выпуски на набор имен (пять на
  имя за 168 часов), и повторные переустановки с удалением каталога caddy
  исчерпывают лимит. Смотрите `docker logs <caddy> | grep rateLimited`.
- **Панель не отвечает снаружи, но отвечает изнутри.** Вас нет в белом списке
  `SEKVYR_ALLOW_IPS`. С самого сервера админка тоже не открывается: соединения с
  хоста приходят к caddy через прокси Docker. Чтобы открыть ее с сервера,
  пробросьте туннель прямо в контейнер фронтенда:
  `ssh -L 8081:<адрес контейнера>:8080 <сервер>`, адрес виден в `docker inspect`
  контейнера фронтенда.
- **По IPv6 не пускает, хотя адрес в списке.** У сети `caddy` нет IPv6, см.
  "Что получилось". Существующей сети IPv6 не добавить, она пересоздается
  вместе со всем, что к ней подключено: `docker network inspect caddy` покажет
  контейнеры; остановите их стеки (`docker compose down`), выполните
  `docker network rm caddy && docker network create --ipv6 caddy` (Docker до 27
  нужна еще подсеть: `--subnet fd00:cad::/64`) и поднимите стеки снова. Или
  публикуйте caddy только на IPv4.
